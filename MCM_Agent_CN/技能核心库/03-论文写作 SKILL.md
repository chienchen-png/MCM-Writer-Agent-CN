# 03-论文写作 SKILL

## 触发条件

当用户指令包含以下关键词时激活：
- "写第X问"（X=1/2/3/4）
- "撰写XX部分" / "撰写XX章节"
- "写摘要" / "写问题重述" / "写模型假设" 等具体章节名
- "继续写作" / "补充内容"

## 前置条件检查

执行前必须确认：
1. `当前赛题/论文草稿/论文大纲_草稿.md` 已存在
2. 对应问题的 `建模思路文档` 已存在
3. 对应问题的 `编程计算结果` 已存在

若不存在，提示用户先完成前置步骤。

## 核心指令

### 步骤 1：写作前准备
1. 读取 `当前赛题/赛题原文/问题陈述.md`，理解题干背景与各问题之间的逻辑关系。
2. 读取 `当前赛题/论文草稿/论文大纲_草稿.md`，确认当前写作位置。
3. 读取对应的 `知识库/模板与规范/范文模板/{A,B,C}题.md` 中该章节的写作技巧。
4. 读取对应的 `当前赛题/建模思路/QX_建模思路文档.md`。
5. 读取对应的 `当前赛题/编程计算结果/QX_运行结果.md`。
6. 读取 `知识库/模板与规范/图标模板/图表模板与撞色配色设计.md`（配色参考）。

### 步骤 2：图表处理

在正式写作前，检查本章节所需的图表是否已存在。

#### 图表处理规则

```
检查 论文草稿/图表/ 目录：
├── 图表 PNG/drawio 文件已存在？
│   └── ✅ 直接插入引用："如图X-Y所示"，配合图片路径
│
└── 图表文件不存在？
    └── 📝 使用【图表占位】标注，交由团队建模手后续绘制
       格式：【图表占位：图X-Y | 图表类型 | 内容描述 | 配色建议】
       示例：【图表占位：图3-1 | 流程图 | 遗传算法求解排产问题的流程步骤 | draw.io】
       示例：【图表占位：图3-2 | 折线图 | 方案一/二/三的收敛曲线对比 | 方案A配色】
```

> ⚠️ **职责边界**：Agent 负责文字写作，团队建模手负责图表绘制。Agent 不在此阶段自动触发 04-Skill 绘制图表，以防止 token 浪费。如需绘图，用户可明确说"画图"触发 04-Skill 的绘制模式。

### 步骤 3：文献引用决策与检索

在正式写作前，根据范本章节的引用规范和当前章节内容，决定是否需要引入引用文献。

#### 引用决策流程

```
当前章节 → 读取范文模板「五、文献引用规范」→ 该位置是否通常有引用？
                                                          │
                              ┌───────────────────────────┤
                              ▼                           ▼
                           需要引用                      不需要引用
                              │                           │
                              ▼                           ▼
                  确定引用类型（背景/方法/对比）      跳过，直接写作
                              │
                              ▼
                  从章节内容提取关键词 → 构造 CNKI 检索词
                              │
                              ▼
                  调用 mcp_cnki_cnki_search → 筛选相关文献
                              │
                              ▼
                  选择 1-2 篇最相关文献 → 按范文引用格式插入
```

#### CNKI 搜索执行规范

```
# 搜索词构造规则
- 从当前章节的模型名称、算法名称中提取核心词
- 结合赛题领域关键词（从赛题原文中提取）
- 使用中文关键词优先，必要时配合英文
- 示例：
  - 写"遗传算法求解排产问题" → search query: "遗传算法 生产排产 优化"
  - 写"多目标规划" → search query: "多目标优化 工厂调度"
  - 写"灵敏度分析" → search query: "灵敏度分析 鲁棒性 优化"

# 调用参数
- db_code: "CJFD"（期刊论文）
- year_start: 当前年份 - 10
- year_end: 当前年份
- max_results: 5
```

#### 引用插入格式

引用格式严格遵循范文模板中的风格：
- 上标格式：`[1]`, `[2-4]`
- 典型句式：
  - "文献[1]提出了基于...的优化方法"
  - "借鉴文献[2]中...的思想，本文..."
  - "与文献[3]的研究结论一致，..."

#### 引用核查清单

写入引用后自查：
1. ✅ 引用文献来自 CNKI 真实搜索结果
2. ✅ 引用数量符合范文模板中该章节的正常范围
3. ✅ 未虚构任何参考文献
4. ✅ 所有引用已同步添加至 `论文草稿/分章节/11_参考文献.md`

### 步骤 4：分段写作

严格按以下原则写作：

#### 写作原则（不可违反）

1. **不编造数据**：所有表格数据必须从 `编程计算结果` 文件中直接引用。如数据缺失，使用 `【占位_描述性说明】` 标注。
2. **公式规范**：
   - 所有公式使用 LaTeX 语法：`$$ ... $$`（独立公式）或 `$ ... $`（行内公式）
   - 变量符号必须与建模思路文档中的符号**严格一致**
   - 每个公式应有编号：`\tag{1}`、`\tag{2}` 等
3. **图表引用**：
   - 已有图表 → 使用 Markdown 图片语法插入：`![图X-Y](图表/图X-Y.png)`，配合引用语句"如图X-Y所示"
   - 缺失图表 → 使用占位符：`【图表占位：图X-Y | 类型 | 描述】`，提醒团队建模手后续绘制
4. **参考范文模板**：模仿范文的语言风格、详略安排、段落衔接方式。
5. **引用规范**：引用文献须来自 CNKI 数据库真实检索结果，不得虚构参考文献；引用位置和数量需参考范文模板中对应获奖等级的引用分布模式；每处引用必须有对应的参考文献条目。
6. **占位符规则**：暂时无法确定的数值、图表，一律使用占位符标注。图表占位符格式：
   - `【图表占位：图X-Y | 图表类型 | 内容描述 | 配色建议】`
   - 示例：`【图表占位：图3-1 | 流程图 | 遗传算法求解排产问题的步骤流程 | draw.io】`
   - 示例：`【图表占位：图3-2 | 折线图 | 方案一/二/三的收敛曲线对比 X轴=迭代次数 Y轴=目标函数值 | 方案A配色】`
   - 示例：`【数值占位：具体数值 需编程确认】`

#### 去 AI 味写作规范（与原则 1-6 同等重要，不可违反）

> **核心理念**：不是"写"论文，而是"模仿"范文。每写一段前，先回想范文中对应章节的语言节奏。数学建模论文的理想风格是 **"简洁、直接、像人写的实验报告"**，而非"华丽、堆砌、像 AI 生成的学术八股"。
>
> **底线原则**：不制造语病，不刻意写错。所有改动都必须让论文变得**更像人**而非**更差**。

##### 7a. 禁用表达替换表

以下词汇/句式是 AI 文本的高频特征，必须避免。优先从范式模板中学习自然的替换方式：

| 禁用（AI 高频） | 说明 | 替换方向 |
|-----------------|------|---------|
| 首先 / 其次 / 再次 / 最后 | 逻辑链条过于显性 | 用序号 `(1) (2) (3)` 或直接衔接 |
| 此外 / 不仅如此 / 更重要的是 | 堆砌递进 | 缩减为"另外"或直接合并 |
| 总而言之 / 综上所述 | 万能句尾 | 用"综上"或省略，直接给出结论 |
| 通过……从而…… | 因果关系过于平滑 | 拆开："……，进而……" 或 "……，由此……" |
| 进行了 / 开展了 | 虚词冗余 | 用具体动词：分析了 / 计算了 / 求解了 |
| 具有一定的 | 冗余限定 | 删除"一定的"，或保留"具有" |
| 存在着 | "着"冗余 | 用"存在" |
| 这充分说明了 | 过度肯定 | 改为"这表明"、"可见" |
| 对于……来说 | 冗余介词 | 删除"来说" |
| 在……方面 | 冗余框式 | 精简或删除 |

##### 7b. 标点符号约束

⚠️ 这是 AI 味最容易被识别的地方。

- **引号 `""`**：仅在**首次定义术语**时使用一次。同一术语后文一律不加引号。
  - ✅ "螺旋推进"是指散粒体在螺旋叶片推动下……（仅首次定义）
  - ✅ 螺旋推进的力学分析表明……（后文不加引号）
  - ❌ 本文采用"遗传算法"对"排产问题"进行"优化"

- **破折号 `——`**：每千字不超过 **2 处**。破折号是强调工具，不是万能连接符。
  - ❌ 模型在求解过程中——由于约束复杂——采用了启发式方法——最终得到了满意解

- **冒号 `：`**：不在同一句话中连续使用两个冒号。

- **分号 `；`**：仅在并列分句中使用，不用于普通断句。

##### 7c. 句式多样性规则

AI 文本的核心问题是句长均匀、结构重复。以下规则强制打破这种均匀性：

- **句长节奏**：每 200 字内，至少包含 1 句短句（≤12 字）和 1 句长句（≥35 字）。
- **段首变化**：相邻两段的段首句不得以相同词汇开头（如连续"由…可知""通过…分析"）。
- **结构轮换**：连续 3 个句子不得以相同语法结构开头（如连续 SVO："本文建立了…""模型考虑了…""算法采用了…"）。
  - ✅ 轮换示例："本文建立了非线性规划模型。在此基础上，以最小化总成本为目标。约束条件方面，主要考虑……"

##### 7d. 数值推理规范

AI 文本在"数据→结论"环节最常见的问题是**跳跃推理**——给出数值后直接跳到结论，省略中间推理。

- **禁止**：`"误差为 2.3%，说明模型精度较高"`（数值→模糊结论，无推理链）
- **要求**：每次引用数值后，必须附带推理链。
  - ✅ `"误差为 2.3%，较同类方法（通常误差 3%-5%）降低了约 40%，验证了引入螺旋系数对收敛速度的改善效果"`

##### 7e. 段落节奏控制

- **段长差异**：相邻段落字数应有明显差异（一段 80-150 字，下一段 30-50 字）。
- **拒接模板段**：每段不必都是"主题句→展开→例证→小结"四段式。有些段落可以只有观点+一句话展开，有些可以是数据+简短解读。
- **问题间的"偷懒"**：第二个问题可以写"问题二的建模思路与问题一类似，此处仅给出关键差异和新增约束条件"，这反而更像人类写作。

##### 7f. 范文对齐检查

每写完一个章节后，执行以下自查：

1. 随机抽取本章 200 字，与范文同类章节的 200 字片段对比：
   - 连接词密度是否接近？（AI 通常 > 范文 ×1.5）
   - 句长分布是否接近？（AI 通常句长更均匀）
   - 引号/破折号数量是否接近？（AI 通常更多）
2. 若发现明显偏离，回到范文重新学习该章节的表达节奏，然后重写。

> 📖 参考依据：Kim et al. (2024) 发现人类写作的话语结构变异度显著高于 LLM；Yamashita & Meike (2025) 证实词汇多样性、句法复杂度和语义一致性是区分人机文本的关键特征。本节所有规则均基于以上研究设计，目标是在不引入语病的前提下，让文本通过这些检测维度的"人类性"检验。

#### 各章节写作指引

##### 摘要（最后写）
- 一句话背景引入
- 逐问说明：方法 + 核心结论（1-2句/问）
- 总体结论
- 关键词 4-6 个

##### 问题重述
- 用自己的语言重新组织，不照抄原文
- 突出核心约束和目标
- 建立数学化的表述框架

##### 模型假设与符号说明
- 假设列表（5-8 条），每条有简要理由
- 符号表使用三线表：`| 符号 | 含义 | 单位 |`

##### 模型建立与求解（核心）
- 每问独立成节
- 结构：决策变量 → 目标函数 → 约束条件 → 求解算法 → 结果分析
- 公式推导逐步展开，关键步骤不跳跃
- 结果用表格呈现，配合分析文字

##### 灵敏度分析
- 对关键参数做 ±10% / ±20% 扰动
- 分析目标函数的变化趋势
- 给出模型鲁棒性结论

##### 模型评价与推广
- 优点：3-4 条，结合具体模型特点
- 缺点：2-3 条，诚实但不过度贬低
- 推广方向：2-3 个实际应用场景

## 学术写作风格参考

### 推荐句式
- "本文构建了...模型，以...为目标函数，以...为约束条件。"
- "由表X-Y可知，当参数 α 从 0.5 增加到 0.8 时，目标函数值降低了 12.3%。"
- "对比方案一与方案二可以发现，...方案在...方面具有显著优势。"
- "为进一步验证模型的可靠性，本节对关键参数进行了灵敏度分析。"

### 禁用表达
- ❌ "我们"（用"本文"替代）
- ❌ "我觉得"、"我认为"（用"分析表明"、"结果表明"）
- ❌ 口语化表达如"搞定了"、"差不多"
- ❌ 直接复制题干原文（问题重述除外）

## 错误处理

- 若建模文档与编程结果中的变量名不一致，暂停并提示用户确认。

- 若数据表格过于复杂（超过 10 列），建议拆分为多个小表。
