## PDF 转 Markdown 模块（MinerU）—— 仅用于往届数模竞赛优秀论文

当用户要求将**往届数学建模竞赛论文的 PDF** 转换为 Markdown 时，执行本模块。

> ⚠️ **范围限制**：本模块仅用于往届数模竞赛优秀论文（国赛/美赛/校赛范文）。不用于 CNKI 期刊论文、学位论文或其他学术文献。

### 前置条件

MinerU 必须已部署（参见总控 Agent 1.6 节）。本模块假设：
- MinerU 路径：`F:\MinerU\venv\Scripts\mineru.exe`
- 模型已下载
- 若不可用，引导用户完成 1.6 节配置

### 步骤 A：确认输入与目标赛题类型

1. 确认用户要转换的 PDF 文件路径。
2. 向用户确认该论文的赛题类型（A / B / C），用于确定输出目录。
   - 若用户未指定，根据论文内容或文件名推断（如包含"A题"、"优化"等关键词 → A题）。
   - 若无法判断赛题类型（可能是非数模论文），提醒用户本模块仅用于往届数模竞赛论文，并终止。

### 步骤 B：执行 MinerU 识别

#### B.1 确定识别模式

首先检查是否有 NVIDIA GPU：

```powershell
nvidia-smi 2>&1
```

- **若 GPU 可用（8GB+ 显存）**：使用 `hybrid-engine` 后端，最高精度 + 图片分析。
- **若仅 CPU**：使用 `pipeline` 后端，公式 + 表格识别（不含图片内容分析）。

#### B.2 构建并执行命令

**模式一：CPU / 低显存（默认）**

```powershell
& "F:\MinerU\venv\Scripts\mineru.exe" `
  -p "<PDF绝对路径>" `
  -o "<临时输出目录>" `
  -b pipeline `
  -l ch `
  -m auto
```

**模式二：NVIDIA GPU 8GB+ 显存（高精度）**

```powershell
& "F:\MinerU\venv\Scripts\mineru.exe" `
  -p "<PDF绝对路径>" `
  -o "<临时输出目录>" `
  -b hybrid-engine `
  -l ch `
  --effort high
```

**参数说明**：

| 参数 | 含义 | 取值 |
|------|------|------|
| `-p` | 输入 PDF 路径 | 绝对路径 |
| `-o` | 输出目录 | 临时目录，后续会整理 |
| `-b` | 识别后端 | `pipeline`（CPU）/ `hybrid-engine`（GPU） |
| `-l` | 文档语言 | `ch`（中文）/ `en`（英文） |
| `-m` | 模型模式 | `auto`（自动选择最佳模型） |
| `--effort` | 精度等级 | `high`（仅 hybrid-engine 支持） |

#### B.3 执行自检

首次调用 MinerU 时，先在终端执行一次轻量测试：

```powershell
if (Test-Path "F:\MinerU\venv\Scripts\mineru.exe") {
    Write-Host "✅ MinerU 已安装"
    & "F:\MinerU\venv\Scripts\mineru.exe" --version 2>&1
} else {
    Write-Host "⚠️ MinerU 未找到，请参考总控 Agent 1.6 节配置"
}
```

### 步骤 C：整理输出文件

MinerU 输出目录中会包含多个中间文件，**仅保留最终 Markdown 文件**。

1. 识别 MinerU 输出目录中生成的最终 `.md` 文件（通常位于 `<输出目录>/<PDF文件名>/<PDF文件名>.md` 或类似结构）。
2. 将该 `.md` 文件复制到目标路径：
   ```
   知识库/文献库/范文存档/{A,B,C}题/<论文名称>.md
   ```
3. 删除 MinerU 输出的临时目录（包括 images、tables 等中间文件）。
4. 若 Markdown 中引用了本地图片，将必要的图片复制到范文存档对应目录下。

**文件命名规范**：
```
<年份>_<赛事>_<赛题类型>_<获奖等级>.md

示例：
2023_国赛_A题_国一.md
2024_美赛_B题_F奖.md
2025_校赛_C题_一等奖.md
```

### 步骤 D：输出确认报告

```
📄 PDF 识别完成
═══════════════════════════════════════
输入文件：  xxx.pdf
识别模式：  pipeline / hybrid-engine
输出路径：  知识库/文献库/范文存档/X题/xxx.md
识别功能：  ✅ 公式(LaTeX)  ✅ 表格(HTML)  ✅ 图片分析(GPU时)
处理耗时：  XX 秒
═══════════════════════════════════════
💡 提示：可执行"学习范文"将新文件纳入索引。
```

### 步骤 E：错误处理

| 错误场景 | 处理方式 |
|----------|----------|
| MinerU 未安装 | 输出 1.6 节配置引导 |
| PDF 文件不存在 | 提示用户确认文件路径 |
| 识别超时/失败 | 先尝试降级为 `pipeline` 模式重试（若原为 hybrid-engine） |
| 输出目录无 .md 文件 | 报告 MinerU 输出结构异常，引导用户检查 |
| 中文 OCR 乱码 | 确认 `-l ch` 参数，检查 PDF 是否为扫描件 |

## 核心指令

### 步骤 1：清空与准备
1. 读取 `知识库/文献库/索引清单.md`，了解当前已入库文献。
2. 遍历 `知识库/文献库/范文存档/` 下所有子文件夹（`A题/`、`B题/`、`C题/`），扫描其中的 Markdown 论文文件。
3. 与索引清单对比，识别新入库文件（未在索引清单中的文件）。

### 步骤 2：全量阅读与提取

对每篇范文，提取以下信息并记录：

#### 2.1 基本信息
- **论文题目**：完整的论文标题
- **赛题类型**：A题（连续优化）/ B题（离散优化）/ C题（数据分析）
- **获奖等级**：从文件名或内容中提取

#### 2.2 结构分析
- **文章架构逻辑**：章节划分方式、各章节篇幅占比
- **详略安排**：哪些部分详细展开，哪些部分简要带过

#### 2.3 写作风格
- **摘要及关键词**：完整摘要内容 + 关键词列表
- **各章节撰写风格**：每章的写作特点
  - 问题重述：语言组织方式、如何改写原文
  - 模型假设：假设数量、表述风格
  - 模型建立：推导详细程度、公式排版风格
  - 结果分析：数据呈现方式、分析深度
  - 结论：总结方式

#### 2.4 语言特征
- **高频学术动词**（至少 10 个，附例句）
- **专业表达句式**（至少 5 个完整句式）
- **段落衔接方式**：过渡句、逻辑连接词

#### 2.5 图表特征
- **图表引用习惯与风格**：
  - 平均每章节图表数量
  - 图表类型偏好
  - 引用句式（如"如图X所示"、"表X列出了"）
- **图表配色风格**：主色调、对比色搭配

#### 2.6 文献引用特征
- **引用总数**：`[1]` 格式的参考文献条数
- **文献类型分布**：
  - 中文期刊论文数量及占比
  - 英文学术文献数量及占比
  - 学位论文数量及占比
  - 教材/专著数量及占比
  - 网络资源/标准/专利数量及占比
- **CNKI 可检索文献**：标记哪些参考文献可通过 CNKI 数据库检索获取
- **引用位置分布**：统计各章节（问题重述/模型假设/模型建立/求解/分析/结论）的引用密度
- **核心高被引文献**（3-5篇）：被多篇范文共同引用的经典文献清单（标题、作者、DOI/CNKI链接）
- **获奖等级关联**：标注每条引用统计数据对应的获奖等级（国一/国二/省一），用于建立引用质量-获奖等级对照

### 步骤 3：更新索引清单

将新文件追加到 `知识库/文献库/索引清单.md` 中，格式如下：

```markdown
| 序号 | 文件名 | 赛题类型 | 建模方法 | 核心算法 | 摘要关键词 | 引用数 | 入库时间 |
|------|--------|----------|----------|----------|------------|--------|----------|
| 001 | 2023_国赛A题_国一.md | 优化类 | 整数规划 | 遗传算法 | 调度, 能耗 | 12 | 2026-07-15 |
```

### 步骤 4：更新范文模板

将提取的写作风格信息，写入对应赛题类型的模板文件：
- A题特征 → `知识库/模板与规范/范文模板/A题.md`
- B题特征 → `知识库/模板与规范/范文模板/B题.md`
- C题特征 → `知识库/模板与规范/范文模板/C题.md`

更新方式：在模板文件的对应章节末尾追加新提取的内容，标注来源范文名称和日期。

**特别注意**：文献引用特征（2.6）必须写入模板的「五、文献引用规范」章节，包括：
- 5.1 引用数量统计（按范文逐条填充）
- 5.2 文献类型分布（按赛题类型汇总）
- 5.3 引用位置规律（按章节汇总中位数）
- 5.4 引用风格特征（提取常用引用句式和期刊偏好）
- 5.5 获奖等级与引用特征关联（分国一/国二/省三档统计）

### 步骤 5：输出摘要报告

执行完成后，向用户输出简要报告：
```
📚 文献阅读完成
- 扫描文件数：X
- 新入库文件数：Y
- 更新模板：A题/B题/C题
- 提取高频动词：N个
- 提取句式模板：M个
```

## 输入规范

### 文献阅读与整理模式
- 无特定输入参数，自动扫描 `知识库/文献库/范文存档/` 目录。

### PDF 转 Markdown 模式
- **必需**：PDF 文件路径（用户提供或从对话上下文推断）。
- **可选**：赛题类型（A/B/C，用于确定输出子目录；未指定时尝试推断或放入根目录）。
- **可选**：识别模式（默认自动检测 GPU 选择最优模式）。

## 输出规范

| 输出项 | 路径 | 说明 |
|--------|------|------|
| 索引清单更新 | `知识库/文献库/索引清单.md` | 追加新文献记录 |
| 模板更新 | `知识库/模板与规范/范文模板/{A,B,C}题.md` | 追加写作风格总结 |
| PDF→MD 结果 | `知识库/文献库/范文存档/{A,B,C}题/<文件名>.md` | MinerU 识别后的 Markdown |
| 摘要报告 | 对话输出 | 简要统计信息 |

## 错误处理

### 文献阅读与整理模式
- 若 `范文存档/` 目录为空（仅有 `.gitkeep`），输出："范文存档为空，请先导入范文论文。"
- 若所有文件均已入库，输出："所有范文已索引，无需更新。"
- 若范文文件非 Markdown 格式，跳过并记录警告。

### PDF 转 Markdown 模式
- 若 MinerU 未安装，输出 1.6 节配置引导。
- 若 PDF 文件不存在，提示用户确认文件路径。
- 若识别超时/失败，先尝试降级为 `pipeline` 模式重试（若原为 `hybrid-engine`）。
- 若输出目录无 `.md` 文件，报告 MinerU 输出结构异常，引导用户检查。
- 若中文 OCR 乱码，确认 `-l ch` 参数，检查 PDF 是否为扫描件。
